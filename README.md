# STAMP STUDIO Ver.1

LINEスタンプ用の画像編集を端末内で行う静的Webアプリです。
公開先: https://dogzall.github.io/-stamp-studio/

画像編集・IndexedDB保存・ローカル同梱JSZipによる出力コードを含みます。
開発途中版です。ブラウザ統合テスト・Android実機テストは未完了です。

## PWAインストール調査・修正（1.0.1）

コード上のManifestは元から `name`、192/512px PNG、`display: standalone` を含み、
相対指定の `id`・`start_url`・`scope` は公開先で `/-stamp-studio/` に解決されます。
HTMLのManifestリンク、SW登録スコープも同ディレクトリです。
アイコンの実サイズとPNG署名をローカルで確認済みです。
これらの設定と画像ファイルは変更していません。

Galaxyでショートカットになる直接原因は未確定です。公開先へのHTTP取得は実行環境の制限で失敗し、
別のWeb取得ツールでもアクセスできませんでした。繰り返しの通信試行・ブラウザ起動は行っていません。
公開先のHTTPステータス、MIME、ブラウザコンソール、Chromeのインストール判定は未確認です。

確認できた更新処理の問題に対して、次を修正しました。

- Manifestのcache-first固定をやめ、オンラインでは再検証、オフラインではキャッシュを利用。
- SWを `stamp-studio-v1.0.1` に変更し、アプリ資産をHTTPキャッシュから再検証して取得。
- SW登録に `updateViaCache: none` を指定。
- 新版のキャッシュ保存失敗時は旧版を維持。失敗した新版キャッシュだけを破棄。
- 保存後の明示操作で新版を有効化。初回SW有効化による不要な再読み込みを防止。
- 設定画面にManifest・PNG・SW・standalone状態の確認とSWエラー表示を追加。

画像処理、背景除去、ZIP生成、IndexedDBの処理は変更していません。
SW更新ではIndexedDB、localStorage、他アプリのキャッシュを削除しません。

## Galaxy / Android Chromeでの確認手順

1. 念のため既存プロジェクトをアプリ内の「バックアップ」で保存する。
2. GitHub Pagesのデプロイ完了後、Chromeの通常タブで公開URLを直接開く。
   メッセージアプリ内のブラウザやシークレットタブは使わない。
3. 新版の案内が出たら「保存して更新」を選ぶ。案内が出なければ一度再読み込みして待つ。
   「使い方」で **PWA修正版 1.0.1** と表示されることを確認する。
4. 「PWA設定を確認」を押す。ManifestのURL、start_url、scopeがすべて
   `https://dogzall.github.io/-stamp-studio/` 以下であること、displayがstandaloneであること、
   192/512pxアイコンが読み込み成功、SW状態がactivated、ページ制御が有効であることを確認する。
5. 画面を一度操作して30秒程度待ち、アプリ内のインストールボタン、またはChromeメニューの
   「ホーム画面に追加」から、アプリのインストール案内が出るか確認する。
   メニュー文言だけでなく、起動後のアプリモード表示も確認する。
6. 以前作った単なるショートカットは自動的にPWAへ変換されない。
   古いショートカットの「ホーム画面から削除」を行い、新たにインストールしたアイコンから起動する。
   アプリのアンインストールやサイトデータの削除とは別の操作なので取り違えない。
7. アドレスバーなしで起動し、使い方画面が「アプリモード」になっていることを確認する。
8. 機内モードにして起動・画像編集・保存と再開・ZIP作成を確認する。

インストール案内には端末・Chromeの状態やユーザー操作履歴も関係します。
設定確認が成功しても、Androidでのインストール完了を保証するものではありません。
改善しない場合は、設定確認の結果・Galaxy機種・Android/Chromeバージョン・メニューの表示内容を確認してください。
サイトデータの削除は保存済み作品を失うため、対処として推奨しません。

Chromeの公式条件: https://web.dev/articles/install-criteria

## GitHub Pages

リポジトリ `dogzall/-stamp-studio` の Settings → Pages で、
Deploy from a branch → `main` → `/ (root)` を選択します。
非公開リポジトリでのPages利用可否はGitHubプラン等の条件に従います。
この修正では公開設定やリポジトリの公開範囲は変更していません。

ビルド不要で、`.nojekyll`、HTML、CSS、JavaScript、Manifest、PNG、vendorを配信します。
HTTPSと `/-stamp-studio/` 配下の配信を維持してください。
ローカルで動かす場合はファイルを直接開かず、ローカルHTTPサーバーを使用します。
