# STAMP STUDIO Ver.2（開発版）

無料・ログイン不要のLINEスタンプ制作支援PWAです。画像生成用プロンプトを端末内のテンプレートで作成し、
ユーザーが別の画像生成サービスで作った画像を取り込んで仕上げます。
アプリ内の生成AIモデル、有料API、APIキー、自動送信・自動取得はありません。

- リポジトリ: https://github.com/dogzall/-stamp-studio
- 現行公開URL: https://dogzall.github.io/-stamp-studio/
- 開発ブランチ: `feature/ver2-planning`
- 開発設計: [docs/VER2-PLAN.md](docs/VER2-PLAN.md)
- テスト結果と実機確認: [docs/VER2-TESTS.md](docs/VER2-TESTS.md)

このブランチはブラウザ・Galaxyでの回帰確認前の開発版です。mainのVer.1は変更していません。
Ver.1のPWA・画像読み込み・背景透過・文字入れ・ZIP・オフライン動作はユーザーがGalaxyで確認済みです。
それを今回のVer.2テスト合格と扱ってはいません。

## 制作の流れ

**企画作成 → プロンプトコピー → ChatGPTで画像生成（手動）→ 画像取り込み → 自動仕上げ → プレビュー → ZIP保存**

1. ホームの「AIスタンプ企画から始める」で新規プロジェクトを作成。
   既存の作品に企画を追加する場合は、その作品を開いて「AIスタンプ企画」を選ぶ。
2. キャラクター名・外見・服装・配色・画風・テーマ・背景を指定する。
   日常・仕事・恋愛・敬語それぞれに8種類のテンプレートがあり、セリフは編集可能。
   テーマ変更時、未編集の提案セリフは切り替わり、手入力した内容は保持する。
   「セリフを自動提案」は確認のうえ8種類を置き換える。
3. 「8枚の企画を作成」で表情・ポーズ・画像生成用プロンプトを作る。
   作成済みの表情・ポーズも編集可能。再作成すると表情・ポーズをテーマ案に戻すため確認が出る。
4. 1枚ずつ／8枚まとめてコピー、またはTXT保存する。コピーできない場合は選択用テキストを表示。
   英語の構図指示も付加できるが、ユーザーが入力した設定・表情・ポーズは自動翻訳しない。
5. 「ChatGPTを開く」から別タブへ移動し、ユーザーがプロンプトを貼り付ける。
   ChatGPTの利用条件・ログイン・画像生成回数制限は別サービスの条件による。
   このアプリはChatGPT側での利用を無料・無制限と保証しない。
6. 画像生成後、ユーザーが端末に画像を保存してアプリに戻る。
   PNG・JPEG・WebP、1枚12MB以下・2000万画素以下、最大8枚を取り込む。
   編集用に長辺1024px以下へ縮小する（Ver.1の仕様）。
7. サムネイル・ファイル名・セリフを見ながら01〜08の割り当てを確認。
   番号重複は登録不可。既存画像の差し替えは明示確認が必要。
   読み込み途中の失敗・キャンセルでは既存の画像を変更しない。
8. 「自動仕上げ」でセリフを一括適用。既存文字は既定で保持する。
   上書きを選んでも位置・色・サイズ・縁取りは維持する。
   「文字を調整」で個別編集、「背景を調整」で既存の透過エディターへ移動する。
9. 白・黒・市松背景で確認する。背景除去で欠けた部分はUndo・復元ブラシで調整する。
   「背景編集を元画像からやり直す」は文字設定を残し、Undo可能な状態で画像を戻す。
10. メイン・タブの元画像を選びZIPを保存する。

共通設定は毎枚のプロンプトに含め、文字を描かせず、全身・単独キャラクター・余白・透明背景の希望を指定します。
完全なキャラクター一致・透明背景・LINE審査合格は保証しません。実際の画像生成はユーザーの手動操作です。

## 保存と互換性

- IndexedDBのDB名 `stamp-studio`、DBバージョン1、`projects` ストアを維持。
- 既存プロジェクトの `version: 1`、画像・文字・Undo/Redoのデータ構造は維持。
- 任意の `planning` と各画像の `planIndex` を追加。Ver.1のデータを自動削除・一括移行しない。
- 企画の編集中データも自動保存し、バックアップJSONへ含める。
- Ver.1バックアップは企画なしで復元でき、Ver.2バックアップは企画も検証・復元する。
- 古いVer.1アプリでVer.2バックアップを復元すると、旧アプリは企画情報を扱わない。
  企画の復元にはVer.2を使い、元のバックアップを保管する。
- 画像の並べ替え後も `planIndex` でセリフとの対応を保持する。
- 保存失敗・容量不足は表示。画像登録／一括文字入れの保存失敗時は変更前の画像配列へ戻す。
- ブラウザデータ削除で作品が失われる可能性があるため、定期的にバックアップする。
- 「元画像」はアプリに取り込んだ時点のPNG。端末上の元ファイルそのものは書き換えない。

## ZIPと透過確認

ZIP直下に `01.png`〜`08.png`、`main.png`、`tab.png` の10枚。
スタンプ370×320px、メイン240×240px、タブ96×74px、縦横比維持・透明余白10px。
各PNG1MB以下・ZIP60MB以下、PNG署名・サイズ・透明余白・ZIP内の名前と枚数を検証する。

完全に透明な画像は番号付きのエラー。透明部分がない編集画像には番号付きの警告を出し、
背景を確認済みとして続けるかをユーザーが選ぶ。
出力で透明余白を追加しても、画像内の白背景・焼き込まれた市松模様が自動で消えるわけではない。
LINEの著作権・内容・最新ガイドラインも申請前に確認する。

## PWA・オフライン・公開

Manifestのid `/-stamp-studio/`、start_url `./`、scope `./`、standaloneと既存アイコンは維持。
PWAを再インストールするための識別子変更はしない。
新モジュールも含めたアプリ資産を `stamp-studio-v2.0.0` として事前キャッシュする。
新版取得に失敗した場合は旧版を維持し、更新は保存後の明示操作で切り替える。
更新案内には「更新前にバックアップ」を追加した。
キャッシュ更新ではIndexedDB・localStorage・AMEKAJIのキャッシュを削除しない。

初回オンライン読み込み後、企画・プロンプト作成、画像取り込み、編集、保存・再開、ZIP作成はオフラインで利用する設計。
ChatGPTを開いて画像を生成する工程だけは外部サービスとネット接続が必要。
画像・企画情報を含む通信、CDN実行時依存、解析・追跡スクリプトは追加していない。

レビューとGalaxy回帰確認後に開発PRをmainへマージし、GitHub Pagesのデプロイ完了を待つ。
Settings → Pages → Deploy from a branch → `main` → `/ (root)`。静的配信でビルド不要。
ブランチを作成するだけでは現行Pagesの内容は変わらない。

## テスト

```sh
npm test
```

Node.js 18以上。新機能27件＋PWA14件、**計41件合格**。
DOM/Clipboard/SWの一部は軽量ハーネス・モックであり、実ブラウザの確認とは別。
ZIPスモークテストは有効な小さなPNG10枚でJSZipを往復し、`test-results/zip-smoke.zip` を出力する。
Python zipfile・Pillow・`unzip -t` でも確認済みだが、実Canvasで生成したLINEサイズのZIPを確認した結果ではない。

```sh
npm run test:browser
```

Python・Pillow・Playwright・Chromiumと、ローカルソケットを利用できる環境が必要。
Ver.1のテストを新しい取り込み確認操作へ更新し、企画・コピー・TXT・一括文字入れ・旧データ・オフラインのテストを追加。
今回の環境ではブラウザテストを実行していない。詳しくはテスト結果表を参照。
